# tsv2bam Job Script for use on SI Hydra

Script name: hydra_tsv2bam.qsub

```
## TLDR

EDIT:

STACKS_DIR=/path/to/stacks_directory
POPMAP=/path/to/popmap.txt
READS_DIR=/path/to/paired_end_reads

SUBMIT JOB:

qsub hydra_tsv2bam.qsub

---
```
```
## Overview

This script runs tsv2bam from the Stacks v2.66 pipeline on SI Hydra. Prior to execution, the script performs a validation check to ensure that all required files are present and consistent across the Stacks output directory, population map, and paired-end read directory.
```
```
The script automatically:
- Verifies that the Stacks directory exists.
- Verifies that the population map file exists.
- Verifies that the paired-end read directory exists.
- Checks that every sample listed in the popmap has corresponding *.matches.tsv.gz and *.tags.tsv.gz files.
- Confirms that paired-end read files exist for each sample.
- Ignores filtered read files ending in .rem.1.fq.gz and .rem.2.fq.gz.
- Stops execution if any required files are missing.
- Runs tsv2bam using all allocated CPU threads.
```
```

## Input Files
```
```
### Stacks Output Directory
The Stacks directory must contain outputs generated by ustacks, cstacks, and sstacks.
```
```
### Population Map (Popmap)
The popmap should contain sample names and population assignments.
```
```
### Paired-End Reads Directory
Supported file naming conventions:
- sample01_R1.fastq.gz / sample01_R2.fastq.gz
- sample01_1.fastq.gz / sample01_2.fastq.gz
- sample01.1.fq.gz / sample01.2.fq.gz

Excluded files:
- *.rem.1.fq.gz
- *.rem.2.fq.gz
```
```
## Resource Requests (as default)
- Threads: 32
- Queue: mThM.q
- Total Memory Reservation: 320 GB
- Memory per Slot: 10 GB
- Virtual Memory per Slot: 100 GB
- High-Memory Node: Yes (himem)
```
```
## Directory Configuration
Modify before running:

STACKS_DIR=/path/to/stacks_directory
POPMAP=/path/to/popmap.txt
READS_DIR=/path/to/paired_end_reads
```
```
## Validation Performed
- Checks required directories and files exist.
- Checks sample .matches.tsv.gz files.
- Checks sample .tags.tsv.gz files.
- Checks paired-end FASTQ files.
- Terminates if any required file is missing.
```
```
## tsv2bam Command

tsv2bam -t $NSLOTS -P "${STACKS_DIR}" -M "${POPMAP}" --pe-reads-dir "${READS_DIR}"
```
```
## Why tsv2bam Is Not Run as an Array Job

Unlike ustacks and sstacks, tsv2bam operates on the complete dataset and requires catalog-wide information. It should be run as a single multi-threaded job.
```
```
## Output
Successful execution generates BAM files used by gstacks.

## Notes
- Ensure upstream Stacks steps have completed successfully.
- Sample names must match across the workflow.
- Monitor h_vmem usage during execution. The tsv2bam step can be highly memory-intensive, particularly for large datasets with many samples and paired-end reads. If the job approaches or exceeds the requested virtual memory allocation (h_vmem), consider increasing the h_vmem request and corresponding memory reservation (mres) before rerunning the job.
